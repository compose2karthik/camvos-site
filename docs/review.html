Infrastructure recommendation

Keep GoDaddy as registrar; use Cloudflare DNS and low-cost static hosting for the public website; keep source in GitHub. Sites remains the private design review environment. These are recommendations, not executed account changes.

Choose AWS versus Azure versus an edge-first backend after inspecting the accepted plane documentation and deployment requirements. Do not migrate frozen identity contracts just to match the website host.

Entity registration and mailboxes are not yet established. Continue product and web design while determining the actual operator identity; final policies must describe that operator and real data flows.

Delivery sequence

  1. Design: review positioning, page hierarchy, wireframe and real product assets.
  2. Content: confirm business identity, contact channels, launch availability and data inventory; draft accurate policies.
  3. Public web: implement responsive routes, inquiry delivery, accessibility, metadata, canonical redirects and HTTPS.
  4. Auth foundation: map callback routes to the frozen Identity/Cloud contracts; document ownership and deployment.
  5. Provider registration: verify current Meta and LinkedIn requirements from official sources; request minimum use-case permissions.
  6. Social implementation: provider-neutral connection/publishing capability, operator organisation accounts first; authorized Event client accounts later.

Authentication and social boundary

Desktop / Owner Web → Cloud social application → SocialConnection → credentialReference → secret store → provider adapter.

Proposed callback paths: /oauth/meta/callback and /oauth/linkedin/callback. These names are provisional until mapped to the accepted auth contract and provider configuration.

  • Bind consent and callback state to the authenticated user, organisation and intended connection; reject replay and expired requests.
  • Exchange authorization codes on the server. Keep secrets and tokens out of Desktop, URLs, browser storage, logs and .camvos packages.
  • Use narrowly scoped grants, encrypted secret storage, revocation and audit trails. Apply PKCE where supported by the selected flow.
  • Register working endpoints rather than placeholder callback pages. Include provider-specific deletion handling where required.

Launch acceptance

  • Every published capability has release evidence; planned features are labelled.
  • All navigation and contact paths work. No mock sign-in, dead CTA or untested inbox.
  • Check small mobile, tablet and desktop layouts, keyboard navigation, contrast and reduced-motion behavior.
  • Legal entity, policy contact, retention and service scope are correct.
  • HTTPS, redirects, canonical metadata, social previews and production indexing are verified.
  • Auth flows pass negative tests for state tampering, tenant mismatch, replay, failed authorization and secret leakage.
  • Architecture Book, Baseline Registry, Integration Manifest and Documentation Index remain a gate for serious cross-plane integration.

Inputs needed for production
